## ProtoPNet
Perform classfication using *similiarity* to *learned* prototypes.

Proposed in [Chen et al, This Looks Like That: Deep Learning for Interpretable Image Recognition, NeurIPS 2019](https://proceedings.neurips.cc/paper_files/paper/2019/file/adf7ee2dcf142b0e11888e72b43fcb75-Paper.pdf)

Motivation: Clasisfication decisions made by prototyping particular elements from the image

![[Pasted image 20251030082245.png|300]]
- Each $1\times 1\times D$ "pixels" in a latent image $\mathbf{z}$ of size $H \times W \times D$ from the prototype layer, corresponds to a patch in the original image.
- Prototypes – we'll see how to learn them later – are also $1 \times 1 \times D$ pixels corressponding to input patches
- For each prototype patch, its similarity to each patch from $\mathbf{z}$ is used to obtain a prototype activation map over $\mathbf{z}$.

![[Pasted image 20251030082750.png]]

**Learning prototypes**
$$
\min _{\mathbf{P}, w_{\text {conv }}} \frac{1}{n} \sum_{i=1}^n \operatorname{CrsEnt}\left(h \circ g_{\mathbf{p}} \circ f\left(\mathbf{x}_{\mathbf{i}}\right), \mathbf{y}_{\mathbf{i}}\right)+\lambda_1 \operatorname{Clst}+\lambda_2 \operatorname{Sep},
$$
where Clst and Sep are defined by
$$
\text { Clst }=\frac{1}{n} \sum_{i=1}^n \min _{j: \mathbf{p}_j \in \mathbf{P}_{y_i}} \min _{\mathbf{z} \in \text { patches }\left(f\left(\mathbf{x}_i\right)\right)}\left\|\mathbf{z}-\mathbf{p}_j\right\|_2^2 ; $$
$$
\operatorname{Sep}=-\frac{1}{n} \sum_{i=1}^n \min _{j: \mathbf{p}_j \notin \mathbf{P}_{y_i}} \min _{\mathbf{z} \in \text { patches }\left(f\left(\mathbf{x}_i\right)\right)}\left\|\mathbf{z}-\mathbf{p}_j\right\|_2^2
$$
where Clst is a measure ensuring every image having some patch nearby a prototype of its class, and Sep ensures keeping prototypes from other classes further away.

### Pros and cons of ProtoPNet
**Pros**: Built in explainability in the model
**Cons**: Does not generalise to generic problems, only works when:
- Where you know what information you expect the algorithm to use
- Where the relevant information is spatially restricted
- Where potential confounding information does not overlap with relevant information

## Concept bottleneck model
Motivation: Explanatory pre-defined concepts that you can interact with

Proposed in [Koh et al, Concept Bottleneck Models, ICML 2020](https://proceedings.mlr.press/v119/koh20a.html)

Training points $(x_i, c_i, y_i)$ for input $x_i$, concept vectors $c_i$, outputs $y_i$.
Concept bottleneck $\hat{y}=f(g(x))$ where $\hat{c}=g(x)$ estimates concepts, and $y=f(c)$ estimates outputs from concepts.

Allowing intervention with the concepts, further improving performance:
![[Pasted image 20251030091634.png]]
### Bottleneck models

1. The independent bottleneck learns $\hat{f}$ and $\hat{g}$ independently: $\hat{f}=\arg \min _f \sum_i L_Y\left(f\left(c^{(i)}\right) ; y^{(i)}\right)$, and $\hat{g}= \arg \min _g \sum_{i, j} L_{C_j}\left(g_j\left(x^{(i)}\right) ; c_j^{(i)}\right)$. While $\hat{f}$ is trained using the true $c$, at test time it still takes $\hat{g}(x)$ as input.
2. The sequential bottleneck first learns $\hat{g}$ in the same way as above. It then uses the concept predictions $\hat{g}(x)$ to learn $\hat{f}=\arg \min _f \sum_i L_Y\left(f\left(\hat{g}\left(x^{(i)}\right)\right) ; y^{(i)}\right)$.
3. The joint bottleneck minimizes the weighted sum $\hat{f}, \hat{g}=\arg \min _{f, g} \sum_i\left[L_Y\left(f\left(g\left(x^{(i)}\right)\right) ; y^{(i)}\right)+\right. \left.\sum_j \lambda L_{C_j}\left(g\left(x^{(i)}\right) ; c^{(i)}\right)\right]$ for some $\lambda>0$.
4. The standard model ignores concepts and directly minimizes $\hat{f}, \hat{g}=\arg \min _{f, g} \sum_i L_Y\left(f\left(g\left(x^{(i)}\right)\right) ; y^{(i)}\right)$.

### Arguments against concept bottleneck models
- Concept-based prediction seem to use information from the entire image. Likely incorrect reasoning: image $\to$ species $\to$ concept $\to$ species

![[Pasted image 20251030091900.png|400]]

- Training on hard ground truth concepts can lead to performance drop. Common solution to this is to use soft, predicted concept which further leads to two issues: correlated concepts and leakage when soft concepts contain more bits that discrete ones. The former affects intervention where changing one concept can have unwanted effect, and affect interpretation my misjudging concept performance. The latter violates the Markovian assumption that $y|c \perp x$
