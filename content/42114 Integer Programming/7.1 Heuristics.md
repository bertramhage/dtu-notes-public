## Approximation Heuristics
Purpose-built algorithms that provide a guaranteed bound on solution quality (worst-case behavior)
### Greedy Heuristic (Knapsack)
- **Concept:** Iteratively select items based on a specific "greedy" criteria (e.g., best value-to-weight ratio) until the constraint is met.
- **Pros:** Fast, simple construction.

### Tree Heuristic (for TSP)
- **Method:**
    1. Find the Minimum Spanning Tree (MST) of the graph ($Z_T$).
    2. Double the edges to create an Eulerian graph.
    3. Perform a walk, skipping previously visited nodes (shortcutting).
- **Bound:** Solution $\le 2 \times$ Optimal ($2Z_T$).
- **Quality:** ~1.09 deviation in sample.

### Tree/Matching Heuristic (Christofides)
- **Method:**
    1. Find the MST ($Z_T$).
    2. Identify nodes with odd degrees ($V'$).
    3. Find a Minimum Weight Perfect Matching ($M$) for $V'$.
    4. Combine MST and Matching edges to form an Eulerian graph.
    5. Perform a walk with shortcutting.
- **Bound:** Solution $\le 1.5 \times$ Optimal.
- **Quality:** ~1.07 deviation in sample.
## Construction Heuristics
Algorithms that build a solution from scratch, step-by-step. Often "Greedy" in nature.
### Nearest Neighbour (TSP)
- **Method:** Start at a node. Always move to the closest unvisited node. Repeat until the tour is complete.
- **Pros:** Very fast.
- **Cons:** Can be "trapped" into taking long edges at the end.
### Cheapest Insertion (TSP)
- **Method:** Start with a subtour. Add the unvisited node that causes the _smallest increase_ in tour length.
### Farthest Insertion (TSP)
- **Method:** Start with a subtour. Add the unvisited node that is _farthest_ from the current tour (prioritizes shaping the "outline" of the tour early).
- **Quality:** Often outperforms Nearest Neighbour (1.16 vs 1.26 in sample).
### Savings Heuristic
- **Method:** Rank arcs by cost (ascending). Add arcs in order as long as they do not violate tour constraints, until all cities are visited.
## Improvement Heuristics (Local Search)
Start with a feasible solution and iteratively improve it by searching a "neighbourhood".
### 2-Opt (2-Exchange)
- **Method:** Remove 2 edges from a tour and reconnect the paths in a different valid configuration.
- **Neighbourhood Size:** $O(n^2)$.    
- **Concept:** Removes crossing edges to shorten the path.
### 3-Opt
- **Method:** Remove 3 edges and reconnect them (allows more complex rearrangements than 2-opt).
- **Pros:** Better solutions than 2-opt (~1.04 deviation).
- **Cons:** Slower due to larger neighbourhood size.
## Metaheuristics
General frameworks designed to escape local optima encountered by standard Local Search.
### Tabu Search
- **Concept:** Allows moving to a _worse_ solution to escape a local optimum.
- **Mechanism:** Uses a **Tabu List** (short-term memory) to forbid reversing recent moves or visiting recent solutions, preventing cycles.
- **Stop Criteria:** Time limit, N iterations, or N iterations without improvement.
### Simulated Annealing (SA)
- **Concept:** Probabilistically accepts worse solutions based on a "temperature" ($T$).
- **Mechanism:**
    - If a move improves the solution ($\Delta \le 0$), accept it.
    - If a move is worse ($\Delta > 0$), accept it with probability $e^{-\frac{\Delta}{T}}$.
- **Cooling:** $T$ decreases over time ($T \leftarrow rT$), making the algorithm increasingly selective (converging to simple local search).
## MIP-Based Heuristics
Frameworks using the mathematical structure (Linear Programming relaxation) to guide the search.
### Dive-and-Fix
- **Method:**
    1. Solve LP relaxation.
    2. Identify fractional binary variables.
    3. Fix one variable (e.g., the one closest to 0 or 1) to an integer value.
    4. Resolve LP. Repeat until feasible or infeasible.
- **Pros:** Provides a bound during computation.
### Relax-and-Fix
- **Method:** Partition variables into "Important" ($x^1$) and "Less Important" ($x^2$).
    1. Relax integrality on $x^2$.
    2. Solve to find integer values for $x^1$.
    3. Fix $x^1$.
    4. Re-impose integrality on $x^2$ and resolve.
- **Use Case:** Multi-stage problems (e.g., Operating Room Planning: Open rooms first $\rightarrow$ Assign patients second).
### Beam Search
- **Method:** A variation of Branch and Bound where the number of active nodes at each level is strictly limited to the best $K$ nodes.
