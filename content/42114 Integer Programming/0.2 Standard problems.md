## 0-1 Knapsack Problem
**Concept:** Choosing a subset of items to maximize value without exceeding a weight capacity.

**Standard Expression:**
$$\begin{aligned} \max \quad & \sum_{j=1}^{n} c_{j} x_{j} \\ \text{s.t.} \quad & \sum_{j=1}^{n} a_{j} x_{j} \leq b \\ & x_{j} \in \{0,1\} \end{aligned}$$
- $x_j$: Binary variable (1 if item $j$ is selected, 0 otherwise).
- $c_j$: Profit/Value of item $j$.
- $a_j$: Weight/Cost of item $j$.
- $b$: Total capacity of the knapsack.

**Typical Solving Strategies:**
- **[[#0-1 Knapsack using Branch and Bound|Branch and Bound]]:** Relax $x_j \in [0,1]$, sort items by ratio $c_j/a_j$, fill greedily to get bounds.
- **[[#0-1 Knapsack using Dynamic Programming|Dynamic Programming]]:** $f_r(\lambda) = \max \{ f_{r-1}(\lambda), c_r + f_{r-1}(\lambda - a_r) \}$. Complexity $O(nb)$.
- **[[#0-1 Knapsack using Greedy Heuristic|Greedy Heuristic]]:** Select items with best profit-to-weight ratio first.

---

## Symmetric TSP
**Concept:** Find the shortest tour visiting all $n$ cities exactly once and returning to the start, where distance $i \to j$ equals $j \to i$.

**Standard Expression:**
$$\begin{aligned} \min \quad & \sum_{e \in E} c_{e} x_{e} \\ \text{s.t.} \quad & \sum_{e \in \delta(i)} x_{e} = 2 \quad \forall i \in V \\ & \sum_{e \in E(S)} x_{e} \leq |S| - 1 \quad \forall S \subset V, 2 \leq |S| \leq n-1 \\ & x_{e} \in \{0,1\} \end{aligned}$$
- $x_e$: Binary variable (1 if edge $e$ is used).
- $\delta(i)$: Set of edges incident to vertex $i$ (Degree constraint: enter and leave = degree 2).
- $E(S)$: Edges with both endpoints in subset $S$ (Subtour elimination constraint).

**Typical Solving Strategies:**
- **[[#Symmetric TSP using 1-Tree Relaxation|1-Tree Relaxation]]:** Remove node 1, find MST of remainder + 2 cheapest edges connected to 1. Used for lower bounds.
- **[[#Symmetric TSP using Cutting Planes|Cutting Planes]]:** Start with degree constraints, iteratively add subtour elimination constraints when violated.

---

## Asymmetric TSP (ATSP)
**Concept:** TSP where cost $i \to j$ may differ from $j \to i$.
**Standard Expression:**
$$\begin{aligned} \min \quad & \sum_{i} \sum_{j} c_{ij} x_{ij} \\ \text{s.t.} \quad & \sum_{j: j \neq i} x_{ij} = 1 \quad \forall i \quad \text{(Leave i once)} \\ & \sum_{i: i \neq j} x_{ij} = 1 \quad \forall j \quad \text{(Enter j once)} \\ & \text{Subtour Elimination Constraints} \\ & x_{ij} \in \{0,1\} \end{aligned}$$
- $x_{ij}$: Binary variable (1 if traveling directly from $i$ to $j$).
- First two constraints are the **Assignment Problem** constraints.

**Typical Solving Strategies:**
- **[[#Asymmetric TSP using Assignment Relaxation|Assignment Relaxation]]:** Solve as an Assignment Problem (relax subtours). If solution has subtours, branch or add cuts.

## Uncapacitated Facility Location (UFL)
**Concept:** Balance fixed costs of opening facilities with variable transportation costs to serve clients.
**Standard Expression:**
$$\begin{aligned} \min \quad & \sum_{i \in M} \sum_{j \in N} c_{ij} y_{ij} + \sum_{j \in N} f_{j} x_{j} \\ \text{s.t.} \quad & \sum_{j \in N} y_{ij} = 1 \quad \forall i \in M \\ & y_{ij} \leq x_{j} \quad \forall i \in M, j \in N \quad \text{(Strong Formulation)} \\ & x_{j} \in \{0,1\}, y_{ij} \geq 0 \end{aligned}$$
**Symbols:**
- $x_j$: Binary (1 if depot $j$ is opened).
- $y_{ij}$: Fraction of client $i$'s demand served by depot $j$ (often binary in optimal solution).
- $f_j$: Fixed cost to open depot $j$.
- $c_{ij}$: Cost to serve client $i$ from depot $j$.

**Typical Solving Strategies:**
- **[[#Uncapacitated Facility Location using Greedy Heuristic|Greedy Heuristic]]:** Open depots iteratively to maximize immediate gain.
- **[[#Uncapacitated Facility Location using Dual-Based|Dual-Based]]:** Uses the strong duality of the LP relaxation.
- **[[#Uncapacitated Facility Location using Lagrangian Relaxation|Lagrangian Relaxation]]:** Relax the demand constraint ($\sum y_{ij} = 1$) into the objective.

---
## Set Covering Problem
**Concept:** Select minimum cost sets such that every element in the universe is included in at least one selected set.

**Standard Expression:**
$$\begin{aligned} \min \quad & \sum_{j=1}^{n} c_{j} x_{j} \\ \text{s.t.} \quad & \sum_{j=1}^{n} a_{ij} x_{j} \geq 1 \quad \forall i \in \{1, \dots, m\} \\ & x_{j} \in \{0,1\} \end{aligned}$$
- $x_j$: Binary (1 if set/column $j$ is selected).
- $a_{ij}$: Binary parameter (1 if set $j$ covers element $i$).
- $c_j$: Cost of set $j$.

**Typical Solving Strategies:**
- **[[#Set Covering Problem|Greedy Heuristic]]:** Pick set covering the most uncovered elements per unit cost.
- **[[#Set Covering Problem using Reductions|Reductions]]:** Eliminate dominated rows (elements) or columns (sets) before solving.
- **[[#Set Covering Problem using Lagrangian Relaxation|Lagrangian Relaxation]]:** Relax the covering constraints.

---
## Uncapacitated Lot-Sizing (ULS)
**Concept:** Plan production over time $t$ to meet demands $d_t$ minimizing setup, production, and storage costs.

**Standard Expression (MIP):**
$$\begin{aligned} \min \quad & \sum_{t=1}^{n} (p_{t} y_{t} + h_{t} s_{t} + f_{t} x_{t}) \\ \text{s.t.} \quad & s_{t-1} + y_{t} = d_{t} + s_{t} \quad \forall t \\ & y_{t} \leq M x_{t} \quad \text{(Linking constraint)} \\ & s_{0} = 0, s_{n} = 0, x_{t} \in \{0,1\}, y_{t}, s_{t} \geq 0 \end{aligned}$$
- $y_t$: Amount produced in period $t$.
- $s_t$: Stock at end of period $t$.
- $x_t$: Binary setup variable (1 if production occurs).
- $f_t$: Fixed setup cost.
- $M$: Big-M parameter (usually $\sum_{k=t}^n d_k$).

**Typical Solving Strategies:**
- **[[#Uncapacitated Lot-Sizing using Dynamic Programming|Dynamic Programming]]:** $H(k) = \min_{1 \le t \le k} \{ H(t-1) + f_t + \text{cost to serve } t \dots k \}$. Runs in $O(n^2)$.
- **[[#Uncapacitated Lot-Sizing using Extended Formulation|Extended Formulation]]:** Define variables $w_{it}$ (production in $i$ for demand in $t$). Tighter LP relaxation.
- **[[#Uncapacitated Lot-Sizing using Property|Property]]:** Zero-Inventory Property (produce only when stock is zero).

### 0-1 Knapsack using Branch and Bound
This strategy finds the optimal set of items by exploring a tree of possibilities, using Linear Programming (LP) relaxations to calculate Upper Bounds (UB) and prune branches that cannot improve the best known solution (LB).

**Example:**
Capacity $W = 10$.
- **Item 1:** Value $v_1=40$, Weight $w_1=4$
- **Item 2:** Value $v_2=42$, Weight $w_2=7$
- **Item 3:** Value $v_3=25$, Weight $w_3=5$

**Solution steps:**
1. **Initialize and Sort**
    Calculate value-to-weight ratio ($v_i/w_i$) for all items and sort them in descending order. Set global Lower Bound ($LB$) to $-\infty$ (or greedy integer solution).
    *Example:*
    - Item 1: $40/4 = 10$
    - Item 2: $42/7 = 6$
    - Item 3: $25/5 = 5$
    Order is 1, 2, 3.

2. **Calculate Root Bound (Relaxation)**
    Calculate the Upper Bound ($UB$) by filling the knapsack with ordered items, allowing fractional parts for the last item that fits.
    *Example:*
    - Take Item 1 (Weight 4, Value 40). Remaining Cap: 6.
    - Item 2 needs 7, but only 6 fits. Take fraction $6/7$ of Item 2. Value: $42 \times \frac{6}{7} = 36$.
    - $UB = 40 + 36 = 76$. Current $LB = 40$ (Item 1 only).

3. **Branch**
    Select a variable to branch on (typically the "split" item from the relaxation or simply the next in order). Create two child nodes: one where the item is excluded ($x_i=0$) and one where it is included ($x_i=1$).
    *Example (Branching on Item 2):*
    - Node A: $x_2 = 1$.
    - Node B: $x_2 = 0$.

4. **Process Nodes (Bound & Prune)**
    For each node, calculate the local $UB$ (relaxation with fixed variables).
    - If $UB \leq LB$: **Prune** (no better solution exists here).
    - If Infeasible (Weight $> W$): **Prune**.
    - If Integer solution found: Update $LB$ if better.
    - Otherwise: Branch further.

    *Example Node A ($x_2=1$):*
    - Fixed: Item 2 (Weight 7, Value 42). Rem Cap: 3.
    - Greedy fill: Item 1 needs 4. Take $3/4$ of Item 1. Val: $40 \times 0.75 = 30$.
    - Total: $42 + 30 = 72$. $UB=72$. ($> LB$, keep exploring).
    *Example Node B ($x_2=0$):*
    - Fixed: No Item 2. Cap 10.
    - Greedy fill: Item 1 (4w, 40v) + Item 3 (5w, 25v). Total W: 9.
    - Integer solution found! Value $65$. Update $LB = 65$. $UB = 65$. Prune.

5. **Repeat**
    Continue until all nodes are pruned or solved.
    *Example Continuation:*
    - Node A ($x_2=1$) is not integer. Branch on next item (Item 1).
    - Child A1 ($x_2=1, x_1=1$): Weight $7+4=11 > 10$. **Infeasible**. Prune.
    - Child A2 ($x_2=1, x_1=0$): Rem Cap 3. Fill Item 3 (fraction $3/5$). $UB = 42 + (25 \times 0.6) = 57$.
    - $57 < LB (65)$. **Prune**.
    - **Optimal Solution:** Node B result -> Items 1 and 3, Value 65.

**Julia Script:**
```julia
using JuMP, HiGHS

# Example Data
v = [40, 42, 25] # Values
w = [4, 7, 5]    # Weights
W = 10           # Capacity
n = length(v)

# Model Definition
model = Model(HiGHS.Optimizer)
set_silent(model)

# Variables (Binary for 0-1 Knapsack)
@variable(model, x[1:n], Bin)

# Objective: Maximize Value
@objective(model, Max, sum(v[i] * x[i] for i in 1:n))

# Constraint: Weight Capacity
@constraint(model, sum(w[i] * x[i] for i in 1:n) <= W)

# Solve
optimize!(model)

# Output
println("Optimal Value: ", objective_value(model))
println("Items selected: ", value.(x))
```

### 0-1 Knapsack using Dynamic Programming
This method breaks the problem down into smaller subproblems by calculating the maximum profit for every possible capacity up to the limit, one item at a time.

**Example:**
Maximize Profit. Capacity $W=5$.
- Item 1: Value $3$, Weight $2$.
- Item 2: Value $4$, Weight $3$.
- Item 3: Value $5$, Weight $4$.

**Solution steps:**

1.  **Initialize Table**
    Create a table where rows represent items ($i$) and columns represent capacities ($\lambda$) from $0$ to $W$. Initialize the first row (Item 0) with zeros (no items = no value).
    *Example:*
    Table size: Items $0 \dots 3$, Capacity $0 \dots 5$.
    Row 0 is all zeros.

2.  **Apply Recursion Formula**
    For each item $i$ and capacity $\lambda$, decide whether to include item $i$ or not:
    $$f_i(\lambda) = \max \{ f_{i-1}(\lambda), \quad c_i + f_{i-1}(\lambda - a_i) \}$$
    - **Option 1 (Exclude):** Take the value from the row above at the same capacity ($f_{i-1}(\lambda)$).
    - **Option 2 (Include):** If the item fits ($\lambda \ge a_i$), add its value $c_i$ to the optimal value of the remaining capacity from the previous row.
    - Pick the maximum of these two.

    *Example (Row 1, Item 1: Val 3, Wgt 2):*
    - Capacities $0, 1$: Item 1 doesn't fit ($2 > \lambda$). Value = 0 (from row above).
    - Capacities $2 \dots 5$: Item fits. Value = $\max(0, 3 + f_0(\lambda-2)) = 3$.

    *Example (Row 2, Item 2: Val 4, Wgt 3):*
    - Cap 3: Fits. $\max(f_1(3), 4 + f_1(3-3)) = \max(3, 4 + 0) = 4$.
    - Cap 5: Fits. $\max(f_1(5), 4 + f_1(5-3)) = \max(3, 4 + f_1(2)) = \max(3, 4+3) = 7$.

3.  **Fill the Table**
    Continue until the table is full. The bottom-right cell is the optimal profit.
    *Example:*
    - **Row 3 (Item 3: Val 5, Wgt 4):**
    - Cap 4: Fits. $\max(f_2(4), 5 + f_2(0)) = \max(4, 5) = 5$.
    - Cap 5: Fits. $\max(f_2(5), 5 + f_2(1)) = \max(7, 5 + 0) = 7$.
    - **Max Profit = 7**.

4.  **Backtrack to Find Solution**
    Start from the optimal value (bottom-right). If the value is the same as the cell directly above it, the item was *not* selected. If it is different, the item *was* selected; subtract its weight and move to the previous row.
    *Example (Start at $f_3(5) = 7$):*
    - Is $f_3(5) == f_2(5)$? ($7 == 7$). Yes. **Item 3 not selected.** Move to $f_2(5)$.
    - Is $f_2(5) == f_1(5)$? ($7 == 3$). No. **Item 2 selected.** Remaining cap: $5 - 3 = 2$. Move to $f_1(2)$.
    - Is $f_1(2) == f_0(2)$? ($3 == 0$). No. **Item 1 selected.** Remaining cap: $2 - 2 = 0$. Move to $f_0(0)$.
    - **Solution:** Items 1 and 2.

**Julia Script:**
``` julia
# Data
profits = [3, 4, 5]
weights = [2, 3, 4]
W = 5
n = length(profits)

# DP Table Initialization (rows 0 to n, cols 0 to W)
# Julia is 1-indexed, so row i corresponds to item i-1, col j corresponds to capacity j-1
f = zeros(Int, n + 1, W + 1)

# Fill Table
for i in 1:n
    for w in 0:W
        weight = weights[i]
        val = profits[i]
        if weight > w
            # Item doesn't fit, take value from row above
            f[i+1, w+1] = f[i, w+1]
        else
            # Max of excluding vs including item
            f[i+1, w+1] = max(f[i, w+1], val + f[i, w+1-weight])
        end
    end
end

println("Max Profit: ", f[n+1, W+1])

# Backtracking
selected_items = []
curr_w = W
for i in n:-1:1
    if f[i+1, curr_w+1] != f[i, curr_w+1]
        push!(selected_items, i)
        global curr_w -= weights[i]
    end
end
println("Selected Items: ", reverse(selected_items))
```

### 0-1 Knapsack using Greedy Heuristic
This approach constructs a solution by iteratively choosing the "best" available item based on a specific criterion (usually value-to-weight ratio) until no more items fit. Note that this does not guarantee an optimal solution for the 0-1 (integer) variant, but it is fast.

**Example:**
Maximize Profit. Capacity $W=10$.
- Item 1: Value $15$, Weight $6$.
- Item 2: Value $12$, Weight $5$.
- Item 3: Value $8$, Weight $4$.

**Solution steps:**

1.  **Calculate Ratios**
    Calculate the value-to-weight ratio ($v_i/w_i$) for all items. This metric represents the "bang for the buck".
    *Example:*
    - Item 1: $15/6 = 2.5$.
    - Item 2: $12/5 = 2.4$.
    - Item 3: $8/4 = 2.0$.

2.  **Sort Items**
    Sort the items in descending order based on the calculated ratios.
    *Example:*
    Sorted order: Item 1, Item 2, Item 3.

3.  **Iterative Selection**
    Iterate through the sorted list. If an item fits in the remaining capacity, select it ($x_i=1$) and update the remaining capacity. If it doesn't fit, skip it ($x_i=0$) and move to the next.
    *Example:*
    - **Try Item 1:** Weight 6. Fits in 10? Yes.
      - Select Item 1. Current Profit: 15. Remaining Capacity: $10 - 6 = 4$.
    - **Try Item 2:** Weight 5. Fits in 4? No.
      - Skip Item 2.
    - **Try Item 3:** Weight 4. Fits in 4? Yes.
      - Select Item 3. Current Profit: $15 + 8 = 23$. Remaining Capacity: $4 - 4 = 0$.

4.  **Final Solution**
    Stop when no more items fit or the list is exhausted.
    *Example:* Total Profit = 23. Selected Items: {1, 3}.
    *(Note: In this specific small case, it matches the optimal solution found by Branch & Bound, but often it might be suboptimal).*

**Julia Script:**
``` julia
# Data
profits = [15, 12, 8]
weights = [6, 5, 4]
W = 10
n = length(profits)

# 1. Create a list of tuples/structs to keep track of original indices
# Calculate ratios and store (ratio, original_index)
items = []
for i in 1:n
    ratio = profits[i] / weights[i]
    push!(items, (ratio, i))
end

# 2. Sort descending by ratio
sort!(items, by = x -> x[1], rev = true)

# 3. Iterative Selection
current_weight = 0
current_profit = 0
selected_items = Int[]

for item in items
    idx = item[2]
    if current_weight + weights[idx] <= W
        push!(selected_items, idx)
        global current_weight += weights[idx]
        global current_profit += profits[idx]
    end
end

println("Total Profit: ", current_profit)
println("Selected Items (indices): ", selected_items)
```

### Symmetric TSP using 1-Tree Relaxation
This method provides a lower bound for the Symmetric Traveling Salesman Problem (STSP) by relaxing the requirement that the tour must be a simple cycle, instead finding a minimum "1-tree" which is a tree plus one edge. This bound is often used inside a Branch and Bound algorithm.

**Example:**
Find the lower bound for a TSP on a graph with 4 cities ($1, 2, 3, 4$).
Distances (symmetric):
- (1,2): 10, (1,3): 15, (1,4): 20
- (2,3): 35, (2,4): 25
- (3,4): 30

**Solution steps:**

1.  **Select a "Special" Node**
    Choose any node (commonly node 1) to be the special node. Remove this node and all incident edges from the graph.
    *Example:*
    - Special Node: 1.
    - Remaining nodes: $\{2, 3, 4\}$.
    - Remaining edges: $(2,3)=35, (2,4)=25, (3,4)=30$.

2.  **Find Minimum Spanning Tree (MST)**
    Calculate the Minimum Spanning Tree for the remaining subgraph (nodes $2, 3, 4$).
    *Example:*
    - Edges available: $(2,3)=35, (2,4)=25, (3,4)=30$.
    - Smallest edge: $(2,4)$ with cost 25. Select it.
    - Next smallest: $(3,4)$ with cost 30. Select it.
    - All nodes $\{2, 3, 4\}$ are connected.
    - **MST Cost:** $25 + 30 = 55$. Edges: $\{(2,4), (3,4)\}$.

3.  **Add Two Cheapest Edges to Special Node**
    Find the two cheapest edges connecting the special node (Node 1) to the rest of the graph and add them to the MST.
    *Example:*
    - Edges incident to 1: $(1,2)=10, (1,3)=15, (1,4)=20$.
    - Two cheapest: $(1,2)$ and $(1,3)$.
    - **Cost to add:** $10 + 15 = 25$.

4.  **Calculate Lower Bound**
    Sum the MST cost and the cost of the two edges connected to the special node. This total is the cost of the optimal 1-tree and a lower bound for the TSP.
    *Example:*
    - **Lower Bound:** $55 (\text{MST}) + 25 (\text{Special Edges}) = 80$.
    - *Interpretation:* Any valid TSP tour must cost at least 80. If the 1-tree happens to be a valid tour (every node has degree 2), it is the optimal solution. In this case, degrees are $d(1)=2, d(2)=2, d(3)=2, d(4)=2$. It is a tour! Optimal TSP cost is 80.

**Julia Script:**
``` julia
using Graphs, SimpleWeightedGraphs

# Data (Distance Matrix)
# Nodes 1..4. Note: Symmetric, so only upper triangle needed really.
dist = [
    0  10 15 20;
    10 0  35 25;
    15 35 0  30;
    20 25 30 0
]
n = 4

# 1. Remove Node 1 (Special Node)
# Create subgraph with nodes 2..n
# Mapping: Subgraph node 1 -> Original node 2, etc.
sub_g = SimpleWeightedGraph(n-1)
for i in 2:n
    for j in (i+1):n
        add_edge!(sub_g, i-1, j-1, dist[i,j])
    end
end

# 2. Find MST of Subgraph (Kruskal's algorithm included in Graphs.jl)
mst_edges = kruskal_mst(sub_g)
mst_cost = sum(e.weight for e in mst_edges)

# 3. Find 2 Cheapest Edges connected to Node 1
edges_from_1 = dist[1, 2:n]
sort!(edges_from_1)
special_edges_cost = edges_from_1[1] + edges_from_1[2]

# 4. Calculate Lower Bound
lower_bound = mst_cost + special_edges_cost

println("MST Cost (nodes 2-4): ", mst_cost)
println("Cheapest edges from 1: ", special_edges_cost)
println("1-Tree Lower Bound: ", lower_bound)
```

### Symmetric TSP using Cutting Planes
This method starts by solving a relaxed problem (usually allowing "subtours" like disjoint loops) and iteratively adds constraints ("cuts") to break these loops until a single valid tour remains.

**Example:**
5 Cities ($1, \dots, 5$). Symmetric distances.
Imagine cities $1,2,3$ are clustered together, and $4,5$ are clustered together, far apart.

**Solution steps:**

1.  **Initial Relaxation (2-Matching)**
    Formulate an LP minimizing distance subject only to **Degree Constraints**: every city must have exactly 2 connected edges (enter once, leave once). Ignore subtour constraints initially.
    *Example:*
    $\min \sum c_{ij} x_{ij}$
    s.t. $\sum_{j} x_{ij} = 2$ for all $i=1 \dots 5$.
    $0 \le x_{ij} \le 1$.

2.  **Solve and Check for Subtours**
    Solve the LP. Inspect the solution. If the solution forms a single connected cycle involving all nodes, you are done. If it forms disjoint cycles (subtours), proceed.
    *Example Solution:*
    - Cycle A: $1-2-3-1$ (Triangle). Sum of edges in set $\{1,2,3\}$ is 3.
    - Cycle B: $4-5-4$ (Edge doubled, often happens in LP).
    - This is valid for degree constraints (everyone has 2 edges), but invalid for TSP.

3.  **Identify Violated Subtour**
    Pick a set of nodes $S$ that forms an isolated subtour.
    *Example:* $S = \{1, 2, 3\}$. $|S| = 3$.

4.  **Add Subtour Elimination Constraint (Cut)**
    Add a constraint that prevents this specific closed loop. The constraint states: "You cannot have $|S|$ edges connecting these $|S|$ nodes; you can have at most $|S|-1$."
    $$\sum_{i, j \in S} x_{ij} \le |S| - 1$$
    *Example:*
    Add constraint: $x_{12} + x_{23} + x_{13} \le 2$.
    (Currently, $1 + 1 + 1 = 3$, so this cuts off the current solution).

5.  **Re-Solve**
    Solve the LP again with the new constraint included. Repeat steps 2-5 until the solution is a single tour.

**Julia Script:**
``` julia
using JuMP, HiGHS, LinearAlgebra, Graphs

# Data (5 cities)
# 1-3 close, 4-5 close, far apart
C = [
    0 10 10 100 100;
    10 0 10 100 100;
    10 10 0 100 100;
    100 100 100 0 10;
    100 100 100 10 0
]
n = 5

model = Model(HiGHS.Optimizer)
set_silent(model)

# Variables (Symmetric: only i < j)
@variable(model, x[1:n, 1:n], Bin)

# Objective
@objective(model, Min, sum(C[i,j] * x[i,j] for i=1:n, j=1:n if i < j))

# Degree Constraints (2 edges per node)
for i in 1:n
    @constraint(model, sum(x[min(i,j), max(i,j)] for j=1:n if i != j) == 2)
end

# Iterative Cutting Plane Loop
function solve_and_cut()
    while true
        optimize!(model)
        val_x = value.(x)
        
        # Build graph from solution to find subtours
        g = SimpleGraph(n)
        for i=1:n, j=i+1:n
            if val_x[i,j] > 0.5 add_edge!(g, i, j) end
        end
        
        components = connected_components(g)
        
        if length(components) == 1
            println("Optimal Tour Found: Cost = ", objective_value(model))
            break # Single tour found
        else
            println("Subtours found: ", components)
            # Add cut for each subtour
            for S in components
                # sum(x_ij for i,j in S) <= |S| - 1
                @constraint(model, sum(x[min(i,j), max(i,j)] for i in S, j in S if i < j) <= length(S) - 1)
            end
        end
    end
end

solve_and_cut()
```

### Asymmetric TSP using Assignment Relaxation
This method solves the ATSP by initially treating it as an **Assignment Problem (AP)**—minimizing cost while ensuring every city is entered once and left once—and then iteratively eliminating any "subtours" (disjoint loops) that appear in the solution.

**Example:**
3 Cities ($1, 2, 3$). Cost Matrix $C$ (Asymmetric):
- $1 \to 2$: 10, $1 \to 3$: 20
- $2 \to 1$: 15, $2 \to 3$: 10
- $3 \to 1$: 20, $3 \to 2$: 50

**Solution steps:**

1.  **Formulate as Assignment Problem (AP)**
    Ignore the "single tour" requirement. Just ensure flow conservation (1 in, 1 out).
    $$\min \sum c_{ij} x_{ij}$$
    $$\text{s.t. } \sum_j x_{ij} = 1 \quad \forall i, \quad \sum_i x_{ij} = 1 \quad \forall j$$

2.  **Solve the AP**
    Solve the linear assignment problem (usually very fast).
    *Example:*
    - Cheapest out of 1: $1 \to 2$ (10)
    - Cheapest out of 2: $2 \to 3$ (10)
    - Cheapest out of 3: $3 \to 1$ (20)
    - **Total Cost:** $10 + 10 + 20 = 40$.
    - **Result:** $1 \to 2 \to 3 \to 1$.

3.  **Check for Subtours**
    Trace the path from the solution.
    - If it visits all $n$ cities in one loop: **Optimal Solution Found**.
    - If it breaks into disjoint loops (e.g., $1 \to 2 \to 1$ and $3 \to 3$): **Subtours Exist**.

4.  **Eliminate Subtours (Branch or Cut)**
    If subtours exist, you must forbid them.
    - **Cutting Plane Strategy:** Add a constraint for the specific subtour detected ($S$).
      $$\sum_{i \in S, j \in S} x_{ij} \leq |S| - 1$$
    - **Branch and Bound Strategy:** Create child nodes where you forbid specific edges from the subtour (e.g., Branch 1: $x_{12}=0$, Branch 2: $x_{23}=0$, etc.) and re-solve.

**Julia Script (Iterative Cutting Plane):**
``` julia
using JuMP, HiGHS, Graphs

# Asymmetric Cost Matrix
C = [
    100 10  20  100;
    15  100 10  100;
    100 50  100 10;
    20  100 100 100
]
n = 4

model = Model(HiGHS.Optimizer)
set_silent(model)

# Binary Variables (Asymmetric: x[i,j] != x[j,i])
@variable(model, x[1:n, 1:n], Bin)

# Objective
@objective(model, Min, sum(C[i,j] * x[i,j] for i=1:n, j=1:n))

# Assignment Constraints (1 in, 1 out)
for i in 1:n
    @constraint(model, sum(x[i,j] for j=1:n if i!=j) == 1) # Leave i
    @constraint(model, sum(x[j,i] for j=1:n if i!=j) == 1) # Enter i
    @constraint(model, x[i,i] == 0) # No self-loops
end

# Loop to break subtours
while true
    optimize!(model)
    println("Current Objective (Relaxation): ", objective_value(model))
    
    # Extract solution to graph
    g = SimpleDiGraph(n)
    x_val = value.(x)
    for i=1:n, j=1:n
        if x_val[i,j] > 0.5 add_edge!(g, i, j) end
    end

    # Find cycles (subtours)
    cycles = simple_cycles(g)
    if length(cycles) == 1 && length(cycles[1]) == n
        println("Optimal Tour: ", cycles[1])
        break
    end

    # Add cut for each subtour found
    for S in cycles
        if length(S) < n
            println("Subtour detected: ", S)
            @constraint(model, sum(x[i,j] for i in S, j in S if i!=j) <= length(S) - 1)
        end
    end
end
```

### Uncapacitated Facility Location using Greedy Heuristic
This approach constructs a solution by iteratively picking the "best" facility to open (or adding it to the current set) based on which one offers the greatest reduction in total cost (fixed + transportation) at that moment.

**Example:**
3 Clients ($1,2,3$), 2 Potential Depots ($A, B$).
- **Fixed Costs:** $f_A = 100$, $f_B = 80$.
- **Transportation Costs ($c_{ij}$):**
  - Depot A: [10, 10, 10] (to clients 1, 2, 3)
  - Depot B: [5, 20, 5]

**Solution steps:**

1.  **Initialize**
    Start with an empty set of open facilities $S = \emptyset$. The "current cost" is technically infinite (or a very large number) because no client is served.
    *(Alternatively, start with a "dummy" facility with high cost if needed, but usually we just compare the marginal gain of opening the first one).*

2.  **Evaluate Adding Each Closed Facility**
    For every facility $j \notin S$, calculate the total cost if we add $j$ to $S$.
    The cost function for a set of open facilities $S$ is:
    $$\text{Cost}(S) = \sum_{j \in S} f_j + \sum_{i \in \text{Clients}} \min_{j \in S} c_{ij}$$
    *Example (Iteration 1):*
    - **Try adding A:** Fixed = 100. Transport = $10+10+10=30$. Total = 130.
    - **Try adding B:** Fixed = 80. Transport = $5+20+5=30$. Total = 110.

3.  **Select Best Move**
    Pick the facility that results in the lowest total cost. If this cost is better than the current best cost (or for the first step, just the minimum), add it to $S$.
    *Example:* $110 < 130$. **Open Depot B**. Current $S=\{B\}$. Current Cost = 110.

4.  **Iterate**
    Repeat the evaluation for remaining closed facilities. Calculate the new transportation cost for each client (it's the minimum of the new facility's cost and the *current* best cost).
    *Example (Iteration 2):*
    - Current $S=\{B\}$. Current transport costs for clients: $[5, 20, 5]$.
    - **Try adding A:** New Fixed cost = $80 + 100 = 180$.
      - Client 1: $\min(5, 10) = 5$ (Stay with B)
      - Client 2: $\min(20, 10) = 10$ (Switch to A)
      - Client 3: $\min(5, 10) = 5$ (Stay with B)
      - New Transport = $5 + 10 + 5 = 20$.
      - Total with $\{A,B\}$ = $180 + 20 = 200$.
    - **Compare:** Cost with $\{A,B\}$ (200) vs Current Cost (110).
    - Since $200 > 110$, adding A **increases** cost. Do not add.

5.  **Terminate**
    Stop when adding any single remaining facility does not improve the total cost.
    *Result:* Open Depot B. Total Cost = 110.

**Julia Script:**
``` julia
# Data
num_clients = 3
num_depots = 2
fixed_costs = [100.0, 80.0] # A, B
trans_costs = [
    10.0 5.0;   # Client 1 to A, B
    10.0 20.0;  # Client 2 to A, B
    10.0 5.0    # Client 3 to A, B
]

# State
open_depots = Int[]
current_best_trans = fill(Inf, num_clients)
current_total_cost = Inf

# Greedy Loop
while true
    best_depot_to_add = -1
    best_new_cost = current_total_cost
    
    # Try adding each closed depot
    for j in 1:num_depots
        if !(j in open_depots)
            # Calculate potential fixed cost
            potential_fixed = sum(fixed_costs[d] for d in open_depots) + fixed_costs[j]
            
            # Calculate potential transport cost
            potential_trans = 0.0
            for i in 1:num_clients
                potential_trans += min(current_best_trans[i], trans_costs[i, j])
            end
            
            total = potential_fixed + potential_trans
            
            # Check if improvement
            if total < best_new_cost
                best_new_cost = total
                best_depot_to_add = j
            end
        end
    end
    
    # Update or Break
    if best_depot_to_add != -1
        push!(open_depots, best_depot_to_add)
        current_total_cost = best_new_cost
        # Update specific client best costs
        for i in 1:num_clients
            current_best_trans[i] = min(current_best_trans[i], trans_costs[i, best_depot_to_add])
        end
        println("Added Depot ", best_depot_to_add, ". New Cost: ", current_total_cost)
    else
        break # No improvement found
    end
end

println("Final Open Depots: ", open_depots)
```

### Uncapacitated Facility Location using Dual-Based
This approach uses the dual of the Linear Programming relaxation to find a good lower bound and potentially a feasible integer solution. It works by setting dual variables ($v_j, w_{ij}$) to maximize the dual objective, which intuitively means finding the highest prices clients are willing to pay that justify opening facilities.

**Example:**
3 Clients ($i=1,2,3$), 2 Depots ($j=1,2$).
- Fixed Costs $f$: Depot 1 = 4, Depot 2 = 6.
- Transportation Costs $c_{ij}$:
  - Client 1: To Depot 1 = 2, To Depot 2 = 5.
  - Client 2: To Depot 1 = 5, To Depot 2 = 2.
  - Client 3: To Depot 1 = 3, To Depot 2 = 3.

**Solution steps:**

1.  **Formulate Dual**
    The dual of the LP relaxation is:
    $\max \sum_{i} v_i$
    s.t. $\sum_{i} w_{ij} \le f_j \quad \forall j$
         $v_i - w_{ij} \le c_{ij} \quad \forall i, j$
         $w_{ij} \ge 0$.
    *Interpretation:* $v_i$ is the price client $i$ pays. $w_{ij}$ is the "contribution" of client $i$ to opening depot $j$. If $v_i > c_{ij}$, the excess pays for the fixed cost ($w_{ij} = v_i - c_{ij}$).

2.  **Greedy Dual Ascent (Heuristic)**
    Sort all transport costs $c_{ij}$ in ascending order. Increase all $v_i$ simultaneously until a constraint tightens (either $v_i$ hits a $c_{ij}$ or a depot is "fully paid for").
    *Example:*
    Sorted distinct costs: 2, 3, 5.
    - **Start:** $v = [0, 0, 0]$.
    - **Raise all $v$ to 2 (min cost):** $v = [2, 2, 2]$.
      - Client 1 pays transport to Depot 1 (cost 2).
      - Client 2 pays transport to Depot 2 (cost 2).
      - Client 3 is not fully covered (min cost 3).
    - **Calculate Contributions ($w_{ij} = \max(0, v_i - c_{ij})$):**
      - Depot 1: $w_{11} + w_{21} + w_{31} = (2-2) + 0 + 0 = 0 \le 4$.
      - Depot 2: $w_{12} + w_{22} + w_{32} = 0 + (2-2) + 0 = 0 \le 6$.
    - **Raise $v_3$ to next cost (3):** $v = [2, 2, 3]$.
      - Depot 1 contribution: $(2-2) + 0 + (3-3) = 0$.
      - Depot 2 contribution: $0 + (2-2) + (3-3) = 0$.
    - *Note:* Often we just set $v_i$ to the cheapest, then second cheapest cost until $\sum w_{ij} = f_j$.

3.  **Construct Primal Solution**
    Open any depot $j$ that is "fully paid for" ($\sum_i w_{ij} = f_j$). Assign each client to the closest *open* depot.
    *Example Check:*
    Let's try higher prices manually to tighten a depot constraint.
    Try $v = [3, 5, 4]$ (Hypothetical feasible dual).
    - $w$ for Depot 1: $(3-2) + (5-5) + (4-3) = 1 + 0 + 1 = 2 \le 4$. (Not full)
    - $w$ for Depot 2: $0 + (5-2) + (4-3) = 0 + 3 + 1 = 4 \le 6$. (Not full)
    *Correction:* A simpler strategy is usually just solving the LP dual directly.

4.  **Complementary Slackness Check**
    If a primal solution and dual solution satisfy complementary slackness (e.g., if $x_j > 0 \implies \sum w_{ij} = f_j$), it is optimal.

**Julia Script (Solving LP Dual):**
``` julia
using JuMP, HiGHS

# Data
num_clients = 3
num_depots = 2
f = [4.0, 6.0]
c = [
    2.0 5.0;
    5.0 2.0;
    3.0 3.0
]

model = Model(HiGHS.Optimizer)

# Dual Variables
@variable(model, v[1:num_clients])
@variable(model, w[1:num_clients, 1:num_depots] >= 0)

# Dual Objective: Maximize sum of client prices
@objective(model, Max, sum(v))

# Constraints
# 1. Total contribution to depot j <= Fixed cost f_j
for j in 1:num_depots
    @constraint(model, sum(w[i,j] for i in 1:num_clients) <= f[j])
end

# 2. Price - Contribution <= Transport Cost (v_i <= c_ij + w_ij)
for i in 1:num_clients
    for j in 1:num_depots
        @constraint(model, v[i] - w[i,j] <= c[i,j])
    end
end

optimize!(model)

println("Dual Objective (Lower Bound): ", objective_value(model))
println("Client Prices (v): ", value.(v))
println("Contributions (w):")
display(value.(w))

# Check tight depots (Potential to open)
tight_depots = []
val_w = value.(w)
for j in 1:num_depots
    if abs(sum(val_w[:,j]) - f[j]) < 1e-5
        push!(tight_depots, j)
    end
end
println("Tight Depots (Candidates): ", tight_depots)
```

### Uncapacitated Facility Location using Lagrangian Relaxation
This method simplifies the UFL problem by relaxing the constraint that "every client must be served" into the objective function using Lagrange multipliers (prices, $u_i$). This decomposes the problem into separate, easy-to-solve subproblems for each depot.

**Example:**
3 Clients ($i=1,2,3$), 2 Depots ($j=1,2$).
- Fixed Costs $f$: Depot 1 = 4, Depot 2 = 6.
- Transportation Costs $c_{ij}$:
  - Client 1: To Depot 1 = 2, To Depot 2 = 5.
  - Client 2: To Depot 1 = 5, To Depot 2 = 2.
  - Client 3: To Depot 1 = 3, To Depot 2 = 3.

**Solution steps:**

1.  **Define Lagrangian Relaxation**
    Relax the constraint $\sum_j y_{ij} = 1$ (each client served exactly once) with multipliers $u_i$.
    The new objective becomes:
    $\min \sum_i \sum_j c_{ij} y_{ij} + \sum_j f_j x_j + \sum_i u_i (1 - \sum_j y_{ij})$
    Rearranging terms by depot $j$:
    $\min \sum_j [ f_j x_j + \sum_i (c_{ij} - u_i) y_{ij} ] + \sum_i u_i$
    *Goal:* Maximize the lower bound by adjusting $u$.

2.  **Solve Subproblems (for fixed $u$)**
    For a specific set of multipliers $u$ (prices clients pay), solve for each depot $j$ independently:
    - Calculate "reduced costs" $\bar{c}_{ij} = c_{ij} - u_i$.
    - If $\bar{c}_{ij} < 0$, it is profitable to serve client $i$ from depot $j$ (set $y_{ij}=1$).
    - Calculate total profit for depot $j$: $P_j = f_j + \sum_{i: \bar{c}_{ij} < 0} \bar{c}_{ij}$.
    - If $P_j < 0$, open depot $j$ ($x_j=1$). If $P_j \ge 0$, keep closed ($x_j=0$).

    *Example (Initial $u = [3, 3, 3]$):*
    - **Depot 1 ($f_1=4$):**
      - Client 1: $2 - 3 = -1$. (Serve)
      - Client 2: $5 - 3 = 2$. (Don't serve)
      - Client 3: $3 - 3 = 0$. (Indifferent, assume no)
      - Net Cost: $4 + (-1) = 3$. ($>0$, Close Depot 1).
    - **Depot 2 ($f_2=6$):**
      - Client 1: $5 - 3 = 2$.
      - Client 2: $2 - 3 = -1$. (Serve)
      - Client 3: $3 - 3 = 0$.
      - Net Cost: $6 + (-1) = 5$. ($>0$, Close Depot 2).
    - **Result:** Both closed. Lower Bound = $\sum P_j (only if < 0) + \sum u_i = 0 + 0 + 9 = 9$.

3.  **Update Multipliers ($u$)**
    Use Subgradient Optimization.
    - Calculate subgradient $g_i = 1 - \sum_j y_{ij}$ (1 if unserved, < 0 if served > once).
    - Update $u_i \leftarrow u_i + \theta \cdot g_i$ ($\theta$ is step size).
    *Example:* Clients unserved, $g = [1, 1, 1]$. Increase prices $u$ to encourage opening.

4.  **Construct Primal Solution (Heuristic)**
    Based on open depots from the subproblem, assign each client to their closest *open* depot.
    *Example:* If Lagrangian opens Depot 1, assign all clients to Depot 1. Calculate actual cost.

5.  **Iterate**
    Repeat steps 2-4 for a number of iterations or until the gap between Lower Bound (Lagrangian) and Upper Bound (Primal) is small.

**Julia Script:**
``` julia
using LinearAlgebra

# Data
num_clients = 3
num_depots = 2
f = [4.0, 6.0]
c = [
    2.0 5.0;
    5.0 2.0;
    3.0 3.0
]

# Lagrangian Parameters
u = [3.0, 3.0, 3.0] # Initial multipliers
iterations = 10
step_size = 1.0

for iter in 1:iterations
    global u
    
    # --- Step 1: Solve Subproblems ---
    x = zeros(Int, num_depots)
    y = zeros(Int, num_clients, num_depots)
    lagrangian_val = sum(u)
    
    for j in 1:num_depots
        # Calculate contribution of depot j
        val_j = f[j]
        served_clients = []
        
        for i in 1:num_clients
            reduced_cost = c[i,j] - u[i]
            if reduced_cost < 0
                val_j += reduced_cost
                push!(served_clients, i)
            end
        end
        
        # Open depot if profitable (negative cost in this minimization context)
        if val_j < 0
            x[j] = 1
            for i in served_clients
                y[i,j] = 1
            end
            lagrangian_val += val_j
        end
    end
    
    # --- Step 2: Subgradient Update ---
    # g_i = 1 - sum(y_ij)
    subgradient = [1 - sum(y[i,:]) for i in 1:num_clients]
    
    println("Iter $iter | LB: $lagrangian_val | Open: $x | Subgrad: $subgradient")
    
    if all(subgradient .== 0)
        println("Optimal Dual Found.")
        break
    end
    
    # Simple step size update
    u = u .+ (step_size / iter) .* subgradient
end
```

### Set Covering Problem using Greedy Heuristic
The greedy heuristic for the Set Covering Problem (SCP) iteratively chooses the set that covers the most remaining (uncovered) elements per unit cost. This continues until all elements in the universe are covered. While efficient, it provides an approximate solution, not necessarily the optimal one.

**Example:**
Universe $U = \{1, 2, 3, 4, 5\}$.
Available Sets:
- Set A: $\{1, 2, 3\}$, Cost = 10.
- Set B: $\{2, 4\}$, Cost = 5.
- Set C: $\{3, 4, 5\}$, Cost = 8.
- Set D: $\{4, 5\}$, Cost = 3.

**Solution steps:**

1.  **Initialize**
    Start with an empty solution and the full universe of uncovered elements $U_{rem} = \{1, 2, 3, 4, 5\}$.

2.  **Calculate Cost Effectiveness (Ratio)**
    For each available set $S_j$, calculate the "cost per newly covered element":
    $$Ratio_j = \frac{\text{Cost}(S_j)}{|\text{Uncovered elements in } S_j|}$$
    *Example (Iteration 1):*
    - Set A: Covers $\{1, 2, 3\}$ (3 new). Ratio = $10 / 3 \approx 3.33$.
    - Set B: Covers $\{2, 4\}$ (2 new). Ratio = $5 / 2 = 2.5$.
    - Set C: Covers $\{3, 4, 5\}$ (3 new). Ratio = $8 / 3 \approx 2.67$.
    - Set D: Covers $\{4, 5\}$ (2 new). Ratio = $3 / 2 = 1.5$.

3.  **Select Best Set**
    Choose the set with the **lowest ratio** (cheapest per new element). Add it to the solution.
    *Example:* Set D has the lowest ratio (1.5).
    - **Select Set D.**
    - Update $U_{rem} = \{1, 2, 3, 4, 5\} \setminus \{4, 5\} = \{1, 2, 3\}$.

4.  **Iterate**
    Repeat the calculation for the remaining sets, considering only elements that are *still uncovered*.
    *Example (Iteration 2):*
    - $U_{rem} = \{1, 2, 3\}$.
    - Set A: Covers $\{1, 2, 3\}$ (3 new). Ratio = $10 / 3 \approx 3.33$.
    - Set B: Covers $\{2\}$ (4 is covered). Ratio = $5 / 1 = 5.0$.
    - Set C: Covers $\{3\}$ (4, 5 covered). Ratio = $8 / 1 = 8.0$.
    - **Select Set A** (Lowest ratio 3.33).
    - Update $U_{rem} = \{1, 2, 3\} \setminus \{1, 2, 3\} = \emptyset$.

5.  **Terminate**
    Stop when all elements are covered ($U_{rem} = \emptyset$).
    *Result:* Sets selected: {D, A}. Total Cost = $3 + 10 = 13$.
    *(Note: Optimal solution might be B+C = 13, or A+D = 13. In this case, greedy found an optimal one, but often it might not).*

**Julia Script:**
``` julia
# Data
# Universe elements: 1..5
# Sets represented as lists of elements
sets = [
    [1, 2, 3], # Set A (Index 1)
    [2, 4],    # Set B (Index 2)
    [3, 4, 5], # Set C (Index 3)
    [4, 5]     # Set D (Index 4)
]
costs = [10.0, 5.0, 8.0, 3.0]
num_sets = length(sets)
universe = Set(1:5) # Elements to cover

selected_set_indices = Int[]
total_cost = 0.0

# Greedy Loop
while !isempty(universe)
    best_ratio = Inf
    best_set_idx = -1
    
    # Evaluate each set
    for j in 1:num_sets
        if !(j in selected_set_indices)
            # Find intersection size with remaining universe
            newly_covered = intersect(universe, sets[j])
            count = length(newly_covered)
            
            if count > 0
                ratio = costs[j] / count
                if ratio < best_ratio
                    best_ratio = ratio
                    best_set_idx = j
                end
            end
        end
    end
    
    if best_set_idx != -1
        # Add best set
        push!(selected_set_indices, best_set_idx)
        total_cost += costs[best_set_idx]
        
        # Remove covered elements from universe
        setdiff!(universe, sets[best_set_idx])
        
        println("Selected Set ", best_set_idx, ". Cost: ", costs[best_set_idx], ". Ratio: ", round(best_ratio, digits=2))
    else
        println("Error: Cannot cover remaining universe with available sets.")
        break
    end
end

println("Final Selection: ", selected_set_indices)
println("Total Cost: ", total_cost)
```

### Set Covering Problem using Reductions
This strategy simplifies the Set Covering Problem (SCP) before solving it by removing redundant rows (elements) and columns (sets) that are strictly worse than or identical to others. This reduces the problem size without changing the optimal solution value.

**Example:**
Universe $U = \{1, 2, 3\}$.
Sets ($x_j$):
- Set A ($x_1$): $\{1, 3\}$, Cost 5.
- Set B ($x_2$): $\{1, 3\}$, Cost 6.
- Set C ($x_3$): $\{1, 2, 3\}$, Cost 10.
- Set D ($x_4$): $\{2\}$, Cost 2.

**Solution steps:**

1.  **Row Dominance (Redundant Elements)**
    Check if any row $i$ is "dominated" by another row $k$. Row $i$ is dominated by row $k$ if every set that covers $k$ *also* covers $i$.
    *Effect:* If row $i$ is dominated, we can remove it. Satisfying the constraint for $k$ automatically satisfies $i$.
    *Example:*
    - Row 1 covered by $\{A, B, C\}$.
    - Row 3 covered by $\{A, B, C\}$.
    - Row 1 dominates Row 3 (and vice-versa). We can remove Row 3 (Constraint 3 is redundant if Constraint 1 is satisfied).
    - Reduced Matrix: Rows $\{1, 2\}$.

2.  **Column Dominance (Redundant Sets)**
    Check if any column $j$ is "dominated" by another column $k$. Column $j$ is dominated by $k$ if:
    1. Cost($k$) $\le$ Cost($j$).
    2. Rows covered by $k$ $\supseteq$ Rows covered by $j$.
    *Effect:* If column $j$ is dominated, remove it (set $x_j=0$). Why pick a more expensive/less effective set?
    *Example:*
    - Compare A (Cost 5, Covers $\{1,3\}$) vs B (Cost 6, Covers $\{1,3\}$).
    - B costs more for the same coverage. **Remove Set B.**
    - Compare A (Cost 5, Covers $\{1,3\}$) vs C (Cost 10, Covers $\{1,2,3\}$).
    - C covers more, but costs more. Not strictly dominated.

3.  **Singleton Row Reduction (Essential Sets)**
    If a row $i$ is covered by only **one** set $j$, that set *must* be selected ($x_j=1$).
    *Effect:* Select set $j$, add its cost, remove all rows covered by $j$, and remove column $j$.
    *Example:*
    - Row 2 is covered by $\{C, D\}$. (Not singleton).
    - If we had reduced further... let's look at Row 2. Covered by C and D.
    - Cost D = 2, Cost C = 10.
    - Note that C covers $\{1,3\}$ (from row 1) and $\{2\}$ (row 2). A covers $\{1,3\}$ and D covers $\{2\}$. Cost A+D = $5+2=7 < 10$.
    - Effectively, C is dominated by the combination of A and D. We might not catch this with simple pairwise column dominance, but logical reduction helps.

4.  **Repeat**
    Apply these rules iteratively until no more reductions are possible. Then solve the (hopefully smaller) core problem.

**Julia Script:**
``` julia
# Data
# Matrix: Rows = Elements, Cols = Sets
# 1 if set j covers element i
A = [
    1 1 1 0; # Element 1
    0 0 1 1; # Element 2
    1 1 1 0  # Element 3
]
costs = [5.0, 6.0, 10.0, 2.0]
num_rows, num_cols = size(A)
active_rows = trues(num_rows)
active_cols = trues(num_cols)

println("Starting Reductions...")

# 1. Row Dominance
# If row i >= row k (element-wise), row i is "easier" to satisfy or identical.
# Actually, standard definition: if Row i is covered by a subset of sets covering Row k,
# satisfying k implies i. So if A[i,:] >= A[k,:], remove i.
for i in 1:num_rows
    if !active_rows[i] continue end
    for k in 1:num_rows
        if i != k && active_rows[k]
            # Check if row i covers at least everything row k does (and maybe more)
            # This logic can be tricky.
            # Simple rule: If sets(i) >= sets(k), then satisfying k satisfies i. Remove i.
            if all(A[i, :] .>= A[k, :])
                println("Row $i dominated by Row $k. Removing Row $i.")
                active_rows[i] = false
                break
            end
        end
    end
end

# 2. Column Dominance
# If Col j <= Col k (covers subset) AND Cost j >= Cost k, remove j.
for j in 1:num_cols
    if !active_cols[j] continue end
    for k in 1:num_cols
        if j != k && active_cols[k]
            # Check coverage dominance (k covers everything j does) on ACTIVE rows
            covers_better = true
            for r in 1:num_rows
                if active_rows[r] && A[j, r] == 1 && A[k, r] == 0
                    covers_better = false; break
                end
            end
            
            if covers_better && costs[k] <= costs[j]
                println("Set $j dominated by Set $k. Removing Set $j.")
                active_cols[j] = false
                break
            end
        end
    end
end

println("Active Rows: ", findall(active_rows))
println("Active Cols: ", findall(active_cols))
```

### Set Covering Problem using Lagrangian Relaxation
This method relaxes the "must cover every element" constraints into the objective function using Lagrange multipliers (prices). This turns the difficult combinatorial problem into a simple check for each set: "Is it cheap enough relative to the prices of the elements it covers?"

**Example:**
Universe $\{1, 2, 3\}$.
- Set A ($x_1$): Covers $\{1, 2\}$, Cost 10.
- Set B ($x_2$): Covers $\{2, 3\}$, Cost 20.
- Set C ($x_3$): Covers $\{1, 3\}$, Cost 15.

**Solution steps:**

1.  **Define Lagrangian Relaxation**
    Relax the constraint $\sum_j a_{ij} x_j \ge 1$ (each element $i$ covered at least once) using multipliers $u_i \ge 0$.
    Original: $\min \sum c_j x_j$.
    Relaxed: $\min \sum c_j x_j + \sum_i u_i (1 - \sum_j a_{ij} x_j)$.
    Regroup by $x_j$:
    $$\min \sum_j \underbrace{(c_j - \sum_i a_{ij} u_i)}_{\text{Reduced Cost } \bar{c}_j} x_j + \sum_i u_i$$

2.  **Solve Subproblem (for fixed $u$)**
    Calculate the **reduced cost** $\bar{c}_j$ for each set $j$. This represents the "net cost" of the set after subtracting the "value" ($u_i$) of the elements it covers.
    - If $\bar{c}_j < 0$: The set is "profitable". Set $x_j = 1$.
    - If $\bar{c}_j \ge 0$: The set is too expensive. Set $x_j = 0$.
    
    *Example (Initial $u = [5, 5, 5]$):*
    - Set A ($c=10$, covers 1,2): $\bar{c}_A = 10 - (5+5) = 0$. (Indifferent, assume 0).
    - Set B ($c=20$, covers 2,3): $\bar{c}_B = 20 - (5+5) = 10$. (Set $x_B=0$).
    - Set C ($c=15$, covers 1,3): $\bar{c}_C = 15 - (5+5) = 5$. (Set $x_C=0$).
    - **Result:** No sets selected ($x=[0,0,0]$).
    - **Lower Bound:** $\sum \bar{c}_j x_j + \sum u_i = 0 + 15 = 15$.

3.  **Update Multipliers ($u$)**
    Use Subgradient Optimization.
    - Calculate subgradient $g_i = 1 - \sum_j a_{ij} x_j$.
      - $g_i = 1$: Element $i$ is **uncovered**. Price $u_i$ should go up.
      - $g_i \le 0$: Element $i$ is covered (maybe multiple times). Price $u_i$ should go down.
    - Update $u_i \leftarrow \max(0, u_i + \theta \cdot g_i)$.
    
    *Example:* With $x=[0,0,0]$, all elements are uncovered. $g=[1,1,1]$. Prices $u$ increase. Next iteration, sets might become profitable ($\bar{c} < 0$).

4.  **Construct Primal Solution (Heuristic)**
    The Lagrangian solution $x$ might be infeasible (uncovered elements).
    - Keep the sets selected by the Lagrangian ($x_j=1$).
    - If elements are still uncovered, use a simple greedy heuristic (like picking the cheapest available set) to cover them.
    - This gives a valid **Upper Bound**.

5.  **Iterate**
    Repeat steps 2-4. The goal is to maximize the Lower Bound (Lagrangian) while finding good Upper Bounds (Primal).

**Julia Script:**
``` julia
using LinearAlgebra

# Data
# Matrix A: Rows=Elements, Cols=Sets
A = [
    1 0 1; # Element 1 covered by A, C
    1 1 0; # Element 2 covered by A, B
    0 1 1  # Element 3 covered by B, C
]
c = [10.0, 20.0, 15.0]
num_elements, num_sets = size(A)

# Parameters
u = [5.0, 5.0, 5.0] # Initial prices
step_size = 2.0
iterations = 10

for iter in 1:iterations
    global u
    
    # 1. Calculate Reduced Costs
    # c_j - sum(u_i for covered elements)
    reduced_costs = c - A' * u
    
    # 2. Solve Subproblem
    x = zeros(Int, num_sets)
    for j in 1:num_sets
        if reduced_costs[j] < 0 # Strictly negative to select
            x[j] = 1
        end
    end
    
    # Calculate Lower Bound
    lb = dot(reduced_costs, x) + sum(u)
    
    # 3. Calculate Subgradient (1 - coverage)
    # coverage[i] is how many sets cover element i
    coverage = A * x
    subgradient = 1.0 .- coverage
    
    # 4. Primal Heuristic (Make Feasible)
    x_feasible = copy(x)
    uncovered = findall(x -> x < 1, coverage)
    if !isempty(uncovered)
        # Naive fix: just add sets for missing elements
        # Real heuristic would be smarter (Greedy)
        for elem in uncovered
            # Find cheapest set covering this element
            # (Simplified for snippet)
            candidates = findall(A[elem, :] .== 1)
            best_set = candidates[argmin(c[candidates])]
            x_feasible[best_set] = 1
        end
    end
    ub = dot(c, x_feasible)
    
    println("Iter $iter | LB: $lb | UB: $ub | Prices u: $u")
    
    if all(subgradient .== 0) && dot(reduced_costs, x) == 0
        println("Optimal found (Complementary Slackness satisfied).")
        break
    end
    
    # Update Multipliers
    u = max.(0.0, u .+ (step_size / iter) .* subgradient)
end
```

### Uncapacitated Lot-Sizing using Dynamic Programming
This method finds the optimal production plan by utilizing the "Zero-Inventory Property" (production only happens when inventory is zero). It recursively calculates the minimum cost to satisfy demand up to period $k$ by checking all possible "last production periods" $t$.

**Example:**
3 Periods ($t=1,2,3$). Demands $d = [2, 4, 5]$.
- Setup cost $f_t = [12, 10, 10]$.
- Production cost $p_t$ & Holding cost $h_t$ are combined into $c_{it}$ (cost to produce in $i$ for demand in $t$).
- Assume simplified cost to produce in $t$ for demand in $k$: $c_{tk} \times d_k$.
- Let's say marginal production cost is 0, holding cost is 1 per unit per period.
  - Produce in 1 for 1: Cost 0.
  - Produce in 1 for 2: Cost $1 \times d_2 = 4$.
  - Produce in 1 for 3: Cost $2 \times d_3 = 10$.

**Solution steps:**

1.  **Define Cost Parameters**
    Calculate $C_{tk}$, the total variable cost (production + holding) if production in period $t$ covers all demands from $t$ to $k$.
    $$C_{tk} = \sum_{j=t}^k (\text{holding \& production cost for demand } d_j)$$
    *Example:*
    - $C_{11} = 0$.
    - $C_{12} = \text{Hold for } d_2 = 1 \times 4 = 4$. Total var cost for 1 covering 1-2 is $0+4=4$.
    - $C_{22} = 0$.
    - $C_{23} = \text{Hold for } d_3 = 1 \times 5 = 5$. Total var cost for 2 covering 2-3 is $0+5=5$.
    - $C_{33} = 0$.

2.  **Initialize DP**
    Let $H(k)$ be the minimum cost to satisfy demands $1 \dots k$.
    $H(0) = 0$.

3.  **Forward Recursion**
    Calculate $H(k)$ for $k=1$ to $n$:
    $$H(k) = \min_{1 \le t \le k} \{ H(t-1) + f_t + C_{tk} \}$$
    *Interpretation:* The last production run started at $t$ and covered everything up to $k$. The cost is the optimal cost up to $t-1$, plus setup at $t$, plus variable costs from $t$ to $k$.

    *Example:*
    - **k=1:** Only option is $t=1$.
      $H(1) = H(0) + f_1 + C_{11} = 0 + 12 + 0 = 12$.
    - **k=2:** Options $t=1$ (produce 1-2) or $t=2$ (produce 2).
      - $t=1$: $H(0) + f_1 + C_{12} = 0 + 12 + 4 = 16$.
      - $t=2$: $H(1) + f_2 + C_{22} = 12 + 10 + 0 = 22$.
      - **$H(2) = 16$** (Best is $t=1$).
    - **k=3:** Options $t=1, 2, 3$.
      - $t=1$: $H(0) + f_1 + C_{13} = 0 + 12 + (4 + 10) = 26$.
      - $t=2$: $H(1) + f_2 + C_{23} = 12 + 10 + 5 = 27$.
      - $t=3$: $H(2) + f_3 + C_{33} = 16 + 10 + 0 = 26$.
      - **$H(3) = 26$** (Tie between $t=1$ and $t=3$).

4.  **Backtrack**
    Reconstruct the solution.
    *Example:* $H(3)$ came from $t=3$ (or $t=1$). Let's pick $t=3$.
    - Production at 3 covers $3 \dots 3$. Remaining problem: $H(2)$.
    - $H(2)$ came from $t=1$.
    - Production at 1 covers $1 \dots 2$.
    - **Plan:** Produce in 1 (for 1, 2) and 3 (for 3).

**Julia Script:**
``` julia
# Data
demands = [2, 4, 5]
setups = [12.0, 10.0, 10.0] # f_t
holding = 1.0
prod_cost = 0.0 # simplified
n = length(demands)

# 1. Precompute Variable Costs C[t, k]
# Cost to produce in t for demands t..k
C = zeros(Float64, n, n)
for t in 1:n
    current_holding_cost = 0.0
    accumulated_var_cost = 0.0
    for k in t:n
        # Cost for demand d_k produced at t
        # (k-t) periods of holding
        cost_for_dk = demands[k] * (prod_cost + holding * (k-t))
        accumulated_var_cost += cost_for_dk
        C[t, k] = accumulated_var_cost
    end
end

# 2. DP Initialization
H = fill(Inf, n + 1)
H[1] = 0.0 # H[1] corresponds to k=0 (0-indexed logic adjustment)
path = zeros(Int, n + 1) # To store 't' that gave the min

# 3. Forward Recursion
# H[k+1] stores optimal cost for demands 1..k
for k in 1:n
    best_val = Inf
    best_t = -1
    for t in 1:k
        # Cost = Optimal cost up to t-1 + Setup at t + Var cost t..k
        val = H[t] + setups[t] + C[t, k]
        if val < best_val
            best_val = val
            best_t = t
        end
    end
    H[k+1] = best_val
    path[k+1] = best_t
end

println("Min Cost: ", H[n+1])

# 4. Backtracking
curr = n
production_plan = []
while curr > 0
    t = path[curr+1]
    push!(production_plan, "Produce at $t for periods $t to $curr")
    global curr = t - 1
end
println("Plan: ", reverse(production_plan))
```

### Uncapacitated Lot-Sizing using Extended Formulation
This approach reformulates the ULS problem using variables that track *exactly which demand* a production batch satisfies. This "Facility Location" style formulation provides a much tighter LP relaxation (often integer optimal) than the standard formulation.

**Example:**
3 Periods ($t=1,2,3$). Demands $d = [2, 4, 5]$.
- Setup cost $f_t = [12, 10, 10]$.
- Unit production cost $p_t = [3, 3, 3]$.
- Unit holding cost $h_t = [1, 1, 1]$.

**Solution steps:**

1.  **Define Decision Variables**
    - $x_t \in \{0, 1\}$: Produce in period $t$? (Setup variable).
    - $w_{it} \ge 0$: Fraction (or amount) of demand $d_t$ (demand of period $t$) that is produced in period $i$ (where $i \le t$).
    *Note:* In the "amount" version, $w_{it}$ is the quantity produced in $i$ for $t$. In the "fraction" version, $w_{it} \le x_i$ directly links setup.

2.  **Calculate Coefficients ($c_{it}$)**
    Calculate the unit cost to produce in $i$ and hold until $t$.
    $$c_{it} = p_i + \sum_{k=i}^{t-1} h_k$$
    *Example:*
    - $c_{11} = 3$. $c_{12} = 3 + 1 = 4$. $c_{13} = 3 + 1 + 1 = 5$.
    - $c_{22} = 3$. $c_{23} = 3 + 1 = 4$.
    - $c_{33} = 3$.

3.  **Formulate Objective**
    Minimize total Setup + Variable Costs.
    $$\min \sum_t f_t x_t + \sum_t \sum_{i=1}^t (c_{it} \cdot d_t) w_{it}$$
    (Here $w_{it}$ is the fraction of demand $d_t$).

4.  **Define Constraints**
    - **Demand Satisfaction:** For every period $t$, the demand must be met from previous production periods $i \le t$.
      $$\sum_{i=1}^t w_{it} = 1 \quad \forall t$$
    - **Strong Linking:** You can only produce in $i$ if the setup $x_i$ is active.
      $$w_{it} \le x_i \quad \forall i, t$$
      *(This is the key constraint that makes the relaxation strong).*

5.  **Solve**
    This formulation is effectively a UFL problem on a specific graph. The LP relaxation often yields integer $x_i$ directly.

**Julia Script:**
``` julia
using JuMP, HiGHS

# Data
demands = [2, 4, 5]
setup_costs = [12.0, 10.0, 10.0] # f
prod_costs = [3.0, 3.0, 3.0] # p
hold_costs = [1.0, 1.0, 1.0] # h
n = length(demands)

# Precompute Unit Costs c[i,t] (Produce in i for demand in t)
unit_c = zeros(n, n)
for i in 1:n
    for t in i:n
        # Cost = Production at i + Holding from i to t-1
        # Sum of h[k] for k from i to t-1
        holding = (t > i) ? sum(hold_costs[k] for k in i:(t-1)) : 0.0
        unit_c[i, t] = prod_costs[i] + holding
    end
end

model = Model(HiGHS.Optimizer)

# Variables
@variable(model, x[1:n], Bin) # Setup in period i
@variable(model, 0 <= w[1:n, 1:n] <= 1) # Fraction of demand t produced in i

# Objective
# Setup costs + Variable costs (c_it * amount d_t)
@objective(model, Min, sum(setup_costs[i] * x[i] for i in 1:n) + 
                       sum(unit_c[i, t] * demands[t] * w[i, t] for t in 1:n for i in 1:t))

# Constraints
# 1. Demand Satisfaction: Sum of fractions for demand t must be 1
for t in 1:n
    @constraint(model, sum(w[i, t] for i in 1:t) == 1)
end

# 2. Strong Linking: Can't produce in i for t unless setup x[i] is on
for t in 1:n
    for i in 1:t
        @constraint(model, w[i, t] <= x[i])
    end
end

optimize!(model)

println("Min Cost: ", objective_value(model))
println("Production Periods (Setup): ", [i for i in 1:n if value(x[i]) > 0.5])
# Show detailed plan
for t in 1:n
    src = [i for i in 1:t if value(w[i, t]) > 0.5]
    println("Demand period $t satisfied by production in period: $src")
end
```

### Uncapacitated Lot-Sizing using Property
This method relies on the specific structural property of optimal solutions in ULS: the **Zero-Inventory Property**. This property states that production in period $t$ ($y_t > 0$) only occurs if the incoming inventory is zero ($s_{t-1} = 0$). This means any production lot must satisfy the *exact* demand for a set of consecutive future periods.

**Example:**
3 Periods. Demands $d = [2, 4, 5]$.
- Setup cost $f_t = [12, 10, 10]$.
- Unit production cost $p_t = [3, 3, 3]$.
- Unit holding cost $h_t = [1, 1, 1]$.

**Solution steps:**

1.  **Understand the Property**
    The Zero-Inventory Property implies that if we produce in period $t$, we produce exactly enough to cover demands from $t$ up to some future period $k$.
    $$y_t = \sum_{j=t}^k d_j \quad \text{for some } k \ge t$$
    We never produce a "partial" demand for a future period.

2.  **Generate Candidate Plans**
    Instead of checking continuous values for $y_t$, we only check discrete "block" strategies.
    Possible Production Quantities for $y_1$:
    - Cover $d_1$: $2$.
    - Cover $d_1, d_2$: $2+4=6$.
    - Cover $d_1, d_2, d_3$: $2+4+5=11$.
    *(We usually combine this with Dynamic Programming to efficiently find the sequence of these blocks, as shown in the DP method. This property is the **reason** the DP works).*

3.  **Construct Solution (Greedy/Heuristic Check)**
    Without the full DP, we can use this property to check specific "regeneration intervals".
    - **Plan A:** Produce in 1 for 1 ($y_1=2$), Produce in 2 for 2 ($y_2=4$), Produce in 3 for 3 ($y_3=5$).
      Cost: $3(12+10+10) + \text{prod} = 32 + (11 \times 3) = 65$.
    - **Plan B:** Produce in 1 for 1-2 ($y_1=6$), Produce in 3 for 3 ($y_3=5$).
      Cost: Setup $12+10=22$. Prod $11 \times 3 = 33$. Holding $d_2 \times 1 = 4$. Total = $22+33+4 = 59$.
    - **Plan C:** Produce in 1 for 1-3 ($y_1=11$).
      Cost: Setup 12. Prod 33. Holding $d_2 \times 1 + d_3 \times 2 = 4 + 10 = 14$. Total = $12+33+14 = 59$.

4.  **Verification**
    Any optimal solution will be composed of these blocks where $s_{t-1} y_t = 0$.

**Julia Script (Verifying Property on Random Plan):**
``` julia
# Data
d = [2, 4, 5]
n = length(d)

# Generate a random valid plan respecting Zero-Inventory
# A plan is defined by "production points"
production_points = [1, 3] # e.g., Produce at 1 (for 1,2) and 3 (for 3)

y = zeros(Int, n)
s = zeros(Int, n + 1)

current_prod_idx = 1
for t in 1:n
    if t in production_points
        # Calculate how much to produce: sum demands until next prod point
        next_point_idx = findfirst(x -> x > t, production_points)
        end_period = isnothing(next_point_idx) ? n : production_points[next_point_idx] - 1
        
        y[t] = sum(d[t:end_period])
    else
        y[t] = 0
    end
    
    # Update inventory
    s[t+1] = s[t] + y[t] - d[t]
end

println("Production Plan (y): ", y)
println("Inventory Levels (s): ", s[2:end])

# Check Property
property_holds = true
for t in 1:n
    if s[t] > 0 && y[t] > 0 # s[t] is inventory entering t (s_t-1)
        global property_holds = false
        println("Violation at t=$t: Incoming Stock $(s[t]) > 0 AND Production $(y[t]) > 0")
    end
end

if property_holds
    println("Zero-Inventory Property holds.")
end
```
