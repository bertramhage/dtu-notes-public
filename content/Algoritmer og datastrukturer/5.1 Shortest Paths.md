## Problem

>[!info] **Single-source shortest paths (SSSP).**  
> Given a weighted, directed graph $G=(V,E,w)$ with **non-negative** edge weights $w:E\to\mathbb R_{\ge0}$ and a source vertex $s\in V$, compute  
> $$\operatorname{dist}(s,v)=\min_{p:s\leadsto v}\;w(p)\quad\text{for every }v\in V,$$  
> where $w(p)$ is the sum of edge weights on path $p$.

* A **shortest-path tree** (SPT) stores for each $v$ its predecessor
  $v.\pi$ on a shortest $s\!\to\!v$ path.  
* Applications: routing, network design, project scheduling, pipelining …

---

## Fundamental Properties  

* **Reachability assumption.** All vertices are reachable from $s$; thus an SSSP value always exists.  
* **Subpath property.** Any subpath of a shortest path is itself a shortest path between its endpoints.

  **Proof outline.**  
  Let $p=p_1\!\cdot p_2\!\cdot p_3$ be a shortest $s\!\to\!t$ path and suppose a subpath $p_2$ can be replaced by a strictly shorter path $q_2$.  
  Then $p_1\cdot q_2\cdot p_3$ is shorter than $p$—contradiction. $\square$

## Dijkstra’s Algorithm (non-negative weights)

### Relaxation

```text
RELAX(u,v)
    if v.d > u.d + w(u,v)
        v.d = u.d + w(u,v)
        v.π = u
```

### High-level idea  

1. **Initialization**  
   $s.d\!\gets\!0$; for all $v\neq s$: $v.d\!\gets\!\infty$.  
2. Maintain a set $T$ of vertices whose shortest-path distance is
   fixed.  
3. Repeatedly  
   * choose $u\notin T$ with minimum tentative distance  
     ( **EXTRACT-MIN** ),  
   * add $u$ to $T$,  
   * **RELAX** every outgoing edge $(u,v)$ ( **DECREASE-KEY** ).

### Pseudocode

```text
DIJKSTRA(G, s)
    for v in V:
        v.d ← ∞
        v.π ← NIL
        INSERT(Q, v)         # priority queue
    DECREASE-KEY(Q, s, 0)

    while Q ≠ ∅:
        u ← EXTRACT-MIN(Q)
        for each edge (u, v) in E:
            RELAX(u, v)
```

### Correctness sketch  

Inductively assume all vertices in $T$ already have final distances.  
Let $u$ be the next vertex chosen.  
Every $s\!\to\!u$ path leaves $T$ exactly once; its first such edge is
$(v,u)$ with $v\in T$.  
Because edge weights are non-negative and $v.d$ is final,  
$u$ cannot have a shorter path than $v.d+w(v,u)$, which Dijkstra has
just assigned.  

---

### Complexity vs. Priority-Queue Implementation  

| Priority queue | `INSERT` | `EXTRACT-MIN` | `DECREASE-KEY` | Total time |
|----------------|----------|---------------|----------------|------------|
| unsorted array | $O(1)$   | $O(n)$        | $O(1)$         | $O(n^2)$   |
| binary heap    | $O(\log n)$ | $O(\log n)$ | $O(\log n)$ | $O(m\log n)$ |
| Fibonacci heap | **amort.** $O(1)$ | **amort.** $O(\log n)$ | **amort.** $O(1)$ | $O(m+n\log n)$ |

## Shortest Paths on DAGs (Directed Acyclic Graphs)

### Algorithm  

1. Compute a **topological order** $v_1,\dots,v_n$.  
2. Initialize $s.d=0$, others $\infty$.  
3. For $i=1$ to $n$  
   * for each edge $(v_i,v_j)$ **RELAX**$(v_i,v_j)$.

### Correctness  

Topological order ensures every edge is scanned exactly once *after*
its source has its final distance; relaxation therefore records optimal
values.

### Running time  

$O(m+n)$—linear, and works with **negative** edge weights (no cycles).

## Variants of the Shortest-Path Problem  

| Dimension | Possible settings |
|-----------|-------------------|
| **Sources / Targets** | single-source, single-pair, all-pairs |
| **Edge weights** | non-negative (Dijkstra), arbitrary (Bellman–Ford), Euclidean (geometric) |
| **Graph structure** | DAG (linear-time), general directed, undirected |
| **Cycles** | none (DAG), no negative cycles, graphs with negative cycles (detect & report) |

---

## Key Take-aways  

* Subpaths of shortest paths are themselves shortest.  
* **Dijkstra** is a greedy algorithm relying on non-negative weights;
  performance hinges on the priority queue.  
* In a DAG the topological order eliminates the need for a queue,
  giving a linear-time solution—even with negative edges.  
* Different weight domains or graph classes call for specialised
  algorithms and analyses.
