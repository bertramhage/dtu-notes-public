## Dynamic Ordered Sets (DOS)

>[!info] **Goal:** Maintain a set $S$ of key–value pairs that changes over time  
> **Core operations**
>
> | Operation | Description | Typical result |
> |-----------|-------------|----------------|
> | `SEARCH(k)`  | return $x∈S$ with $x.key=k$ or `null` | Boolean / element |
> | `INSERT(x)` | add $x$ (assume unique key) | new |S| = |S|+1 |
> | `DELETE(x)` | remove $x$ | new |S| = |S|−1 |

### Naïve approaches & their costs
| Structure          | `SEARCH`                    | `INSERT` | `DELETE` | Space  |
| ------------------ | --------------------------- | -------- | -------- | ------ |
| Doubly-linked list | $Θ(n)$                      | $Θ(1)$   | $Θ(1)$   | $Θ(n)$ |
| Sorted array       | $Θ(\log n)$ (binary search) | $Θ(n)$   | $Θ(n)$   | $Θ(n)$ |

### Take-away  
Both extremes fail to make **all three** DOS operations efficient.  
We need a structure that keeps keys **ordered** yet adapts in **sub-linear** time ⇒ *search trees*.

## Binary Search Trees (BSTs)

### Definition  
A **binary search tree** is a rooted binary tree where, for every node $v$,

- keys in the *left* subtree are $\le v.key$  
- keys in the *right* subtree are $\ge v.key$

Each node stores  `(key, data, left, right, parent)`.

### Traversals  
- **In-order** (L, V, R) ⟹ keys appear *sorted*  
- **Pre-order** (V, L, R)  
- **Post-order** (L, R, V)

### Core operations ($h$ = tree height)

```  
SEARCH(v, k)  
    if v is null → return null  
    if k = v.key → return v  
    if k < v.key → return SEARCH(v.left, k)  
    else          → return SEARCH(v.right, k)  
```

*Time:* $Θ(h)$

```  
INSERT(v, x)  
    if v is null → return x                // new leaf  
    if x.key ≤ v.key  
        v.left  = INSERT(v.left, x)  
    else  
        v.right = INSERT(v.right, x)  
    return v  
```

*Time:* $Θ(h)$

```  
DELETE(T, x)  
    case 0 children: remove x  
    case 1 child:    splice x’s child into x’s parent  
    case 2 children:  
        y ← successor(x)               // smallest key > x.key  
        swap keys(x, y)                // x now easy case  
        DELETE(T, y)  
```

*Time:* $Θ(h)$

### Height analysis  
- **Worst-case:** inserting sorted keys ⇒ $h = Θ(n)$  
- **Average:** random insertions ⇒ $h = Θ(\log n)$  
- **Challenge:** guarantee $h = Θ(\log n)$ **for *all* sequences**.

## Balanced Search Trees — 2-3 Trees

### Structure  
- Internal nodes have **2 or 3 children**.  
  - **2-node:** 1 key, 2 children.  
  - **3-node:** 2 keys, 3 children.  
- **Perfectly balanced:** every root→leaf path has equal length.  
  ⇒ height $h = Θ(\log n)$ *worst-case*.

### Search  

```  
SEARCH(v, k)  
    if v is leaf → compare & return  
    if k ≤ first key(v)    → SEARCH(child₀, k)  
    else if v is 3-node and k > first key ∧ k ≤ second key  
          → SEARCH(child₁, k)  
    else                   → SEARCH(child₂, k)  
```

*Time:* $Θ(\log n)$

### Insertion (sketch)

1. Find the leaf position via `SEARCH`.  
2. Add the key to the leaf (may now hold 3 keys).  
3. **Split** over-full node: move middle key up, giving two 2-nodes.  
4. Cascade splits up the tree; a root split increases height by 1.

*Time:* $Θ(\log n)$ (at most one split per level)

### Deletion (sketch)

1. Locate key; if internal → swap with successor to move to leaf.  
2. Remove the key from leaf (may now have < 1 key).  
3. **Rebalance**: borrow from a 3-sibling or **merge** with sibling;  
   if parent underflows, continue upward.

*Time:* $Θ(\log n)$

### Summary of balanced DOS structures

| Structure | Height guarantee | `SEARCH` | `INSERT` | `DELETE` | Space |
|-----------|------------------|----------|----------|----------|-------|
| BST (plain) | none | $Θ(h)$ | $Θ(h)$ | $Θ(h)$ | $Θ(n)$ |
| 2-3 tree     | $Θ(\log n)$ | $Θ(\log n)$ | $Θ(\log n)$ | $Θ(\log n)$ | $Θ(n)$ |

Balanced trees (AVL, red-black, B-trees, …) extend this idea, each offering $Θ(\log n)$ worst-case operations while tuning constant factors for different environments (memory, disk, concurrency).
