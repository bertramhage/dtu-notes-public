- Iterative procedure keeps reassigning observations to their closest clusters and recompute the cluster centroids
- Clustering ends when convergence is reached (no new reassignments)

## Density-Based clustering (DBSCAN)

**Density-Based Spatial Clustering of Applications with Noise (DBSCAN)** is an algorithm that groups points based on their density.
* It does **not** require the number of clusters ($K$) to be specified.
* It is robust to noise/outliers.
* It can find arbitrarily shaped clusters (not just spherical ones).

DBSCAN has two key parameters:

* **$\epsilon$ (epsilon)**: The radius of the neighborhood around a point.
* **MinPts**: The minimum number of points required to be within a point's $\epsilon$-neighborhood to form a dense region (a core).

Based on these, points are classified as:
* **Core point**: A point that has at least `MinPts` (including itself) in its $\epsilon$-neighborhood.
* **Border point**: A point that is reachable from a core point (is in its $\epsilon$-neighborhood) but does not have `MinPts` in its own neighborhood.
* **Outlier (Noise)**: A point that is neither a core point nor a border point.

### Formal definitions
* **Directly density-reachable**: A point $z_j$ is directly density-reachable from a point $z_k$ if:

1. $z_j$ is within the $\epsilon$-neighborhood of $z_k$ ($z_j \in N_{\epsilon}(z_k)$).
2. $z_k$ is a core point ($|N_{\epsilon}(z_k)| \ge MinPts$).

* *Note*: This relationship is **not symmetric**. A border point $z_j$ can be directly reachable from a core point $z_k$, but $z_k$ is not directly reachable from $z_j$ (since $z_j$ is not a core point).

* **Density-reachable**: A point $z_j$ is density-reachable from $z_k$ if there is a chain of points $z_1, ..., z_q$ (where $z_1 = z_j$ and $z_q = z_k$) such that each point $z_{l+1}$ is directly density-reachable from $z_l$.
* This relationship is transitive but still **not symmetric**.

* **Density-connected**: Two points $z_j$ and $z_k$ are density-connected if there is a core point $z_0$ from which both $z_j$ and $z_k$ are density-reachable.
* This relationship **is symmetric**.

* **Cluster**: A maximal set of density-connected points.
* **Noise**: The set of points that do not belong to any cluster.

### Practical considerations
* **Varying densities**: DBSCAN struggles with clusters of varying densities, as a single `MinPts` and `$\epsilon$` setting may not work for all clusters.
* **Memory**: Can be memory-demanding.
* **High dimensions**: The concept of "density" becomes less clear in high-dimensional spaces (curse of dimensionality), making it hard to choose parameters.

## Clustering Evaluation
How do we know if a clustering is good?
* **Minimize within-cluster variability** (W): Points within a cluster should be as close as possible.
* **Maximize between-cluster variability** (B): Different clusters should be as far apart as possible.

### Distortion
* Measures the **within-cluster variability (W)**.
* It is the sum of squared distances between each observation ($z_j^{(k)}$) and the centroid ($\overline{z}^{(k)}$) of its assigned cluster.
* A good clustering will have **low distortion**.

### Silhouette
* Measures how well an observation fits its assigned cluster by considering both within-cluster and between-cluster variability.

* The silhouette score $s(z_j)$ for a single observation $z_j$ is:

$$

s(z_{j})=\frac{b(z_{j})-a(z_{j})}{max(b(z_{j}),a(z_{j}))}

$$

* $a(z_j)$: The average distance between $z_j$ and all other points **in its own cluster** (intra-cluster distance). We want this to be **small**.
* $b(z_j)$: The average distance between $z_j$ and all points in the **second nearest cluster**. We want this to be **large**.

* The score ranges from -1 to 1:
* $s(z_j) \rightarrow 1$: The observation is well-matched to its cluster and far from others (ideal).
* $s(z_j) \rightarrow 0$: The observation is on the border between two clusters.
* $s(z_j) \rightarrow -1$: The observation is likely in the wrong cluster.

* The silhouette for the entire dataset is the average of $s(z_j)$ for all observations.

### The Elbow curve

* A method for choosing the optimal number of clusters $K$ (e.g., in K-means).
* **How**: Plot an objective function (like distortion) for different values of $K$
* **Find**: The "elbow point" on the graph—the point where the function's value stops decreasing rapidly. This suggests a point of diminishing returns for adding more clusters.

## Appendix: Other Clustering Methods

### Distribution-Based Clustering (Gaussian Mixture Models)

* **Concept**: Assumes the data is generated from a mixture of $K$ different underlying probability distributions (e.g., $K$ Gaussian/Normal distributions).

* Each distribution $f_k$ represents a cluster.

* **Goal**:

1. Estimate the parameters of these distributions (e.g., mean $\mu_k$ and covariance $\Sigma_k$ for each Gaussian).
2. Estimate the probability $\theta_k$ that an observation comes from each distribution.
3. For each observation, determine the probability it belongs to each cluster.

* **Algorithm**: Typically uses the **Expectation-Maximization (EM) algorithm**.

1. **Initialize**: Guess the $K$ distribution parameters ($\mu_k, \Sigma_k, \theta_k$).
2. **E-step (Expectation)**: Calculate the probability (named $\gamma_{jk}$) that each point $z_j$ belongs to each cluster $k$, based on the current parameters.
3. **M-step (Maximization)**: Re-estimate (update) the distribution parameters ($\mu_k, \Sigma_k, \theta_k$) using the probabilities from the E-step to maximize the log-likelihood.
4. **Loop**: Repeat E-step and M-step until the parameters converge.


**Advantages**:
* Provides probabilistic cluster membership, which is more flexible than K-means' hard assignments.
* Computationally fast.

**Disadvantages**:
* Need to choose a fixed $K$.
* Initialization affects the final results.

### Hierarchical Clustering

* **Concept**: Builds a binary tree of data that successively merges similar groups, rather than requiring a single $K$.

* This structure is visualized using a **Dendrogram**.

* **Types**:
* **Agglomerative (bottom-up)**: Starts with each observation as its own cluster (N clusters) and merges the two most similar clusters until only one cluster remains.
* **Divisive (top-down)**: Starts with all observations in one cluster and recursively splits it (e.g., using K-means with $K=2$) into smaller clusters.
* **Linkage (for Agglomerative)**: Defines how to measure the distance between two clusters.
* **Single linkage**: Minimum distance. The distance between two clusters is the distance between their two *closest* points.
* **Complete linkage**: Maximum distance. The distance is based on the two *farthest* points.
* **Average linkage**: Average distance. The distance is the average of all "all-to-all" distances between points in the two clusters.

**Advantages**:
* Does not require specifying the number of clusters $K$ beforehand.
* Provides a simple, self-organized structural view of the data (the dendrogram).

**Disadvantages**:
* Dendrograms can be difficult to visualize and interpret for large datasets.
* It can be difficult to extract a "flat" set of clusters (i.e., decide where to "cut" the dendrogram).
