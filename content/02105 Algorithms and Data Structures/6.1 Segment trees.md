# Segment trees

Segment trees maintain aggregate information (min, max, sum, …) on
**sub-arrays** while supporting both range queries and point/range
updates in $O(\log n)$ time using only $O(n)$ space.

---

## 1 Problem setting  

Given an array $A[0\ldots n-1]$ we must support  

* **Range Minimum Query**  
  $\text{RMQ}(i,j)=\displaystyle\min_{i\le k\le j}A[k]$
* **Point update**  
  $\text{Add}(i,k):\;A[i]\leftarrow A[i]+k$

A good data structure should achieve $O(\log n)$ for both operations and
$O(n)$ space.

---

## 2 Naïve solutions and their drawbacks

| Structure | Space | $\text{RMQ}$ | $\text{Add}$ |
|-----------|-------|--------------|--------------|
| Raw array | $O(n)$ | $O(n)$ | $O(1)$ |
| Pre-computed matrix | $O(n^{2})$ | $O(1)$ | $O(n^{2})$ |

Segment trees obtain the desired bounds of $O(n)$ space and
$O(\log n)$ per operation.

---

## 3 Tree layout

* A **balanced binary tree** where every leaf corresponds to one
  element of $A$ (pad to a power of two or let the last level be
  partial).
* Each internal node stores **the minimum of its children’s ranges**.
* Height $=$ $\lceil\log_2 n\rceil$ ⇒ at most $2n$ nodes.

### 3.1 Compact (heap) representation

* Array `T[0‥2n-1]`
* Leaves: `T[n+i]=A[i]`
* Internal indices:  
  parent of `j` = $\lfloor j/2\rfloor$, children =`2j`, `2j+1`

---

## 4 Algorithms

### 4.1 Building the tree

```for i = 0 … n-1
    T[n+i] ← A[i]
for i = n-1 downto 1
    T[i] ← min(T[2i], T[2i+1])
```

*Runtime* $=$ $O(n)$.

---

### 4.2 Range minimum query

```a ← i + n; b ← j + n; s ← +∞
while a ≤ b:
    if a is right child (a % 2 = 1):
        s ← min(s, T[a]); a ← a + 1
    if b is left child  (b % 2 = 0):
        s ← min(s, T[b]); b ← b - 1
    a ← ⌊a/2⌋; b ← ⌊b/2⌋
return s
```

At most two nodes per tree level are inspected ⇒
time $O(\log n)$.

---

### 4.3 Point update  

To execute $\text{Add}(i,k)$:

```x ← i + n
T[x] ← T[x] + k
x ← ⌊x/2⌋
while x ≥ 1:
    T[x] ← min(T[2x], T[2x+1])
    x ← ⌊x/2⌋
```

Path length equals tree height ⇒ $O(\log n)$.

---

## 5 Correctness (outline)

*Base* (leaves): each leaf holds the exact element value.  
*Induction*: if both children of a node store correct minima,
that node’s value `min(left,right)` is the correct minimum for the
union interval.  
Updates only modify the root-to-leaf path; re-computing on the way up
restores the invariant.

---

## 6 Complexity summary

| Operation | Time | Extra space |
|-----------|------|-------------|
| Build | $O(n)$ | $O(n)$ (array `T`) |
| $\text{RMQ}$ | $O(\log n)$ | $O(1)$ |
| $\text{Add}$ | $O(\log n)$ | $O(1)$ |

---

## 7 Variants and extensions

* **Other operators**: replace `min` with any associative
  function (max, sum, gcd, xor, …).
* **Lazy propagation**: store pending updates in internal nodes to
  support *range updates* with the same $O(\log n)$ bounds.
* **Static RMQ**: without updates, a sparse table answers queries in
  $O(1)$ time using $O(n\log n)$ preprocessing space, or
  $O(n)$ space with Euler tour–based solutions.
* **Higher dimensions**: nesting forms $k$-D segment trees
  (time $O(\log^{k} n)$, space $O(n\log^{k-1} n)$).

---

## 8 Key takeaways

1. Segment trees provide a general-purpose, lightweight tool for
   problems mixing contiguous range queries with updates.
2. The array (heap) layout eliminates pointers, is cache-friendly and
   simple to implement.
3. For many algorithm-competition and systems tasks, segment trees are
   the go-to data structure before resorting to more exotic balanced
   trees or Fenwick trees.
